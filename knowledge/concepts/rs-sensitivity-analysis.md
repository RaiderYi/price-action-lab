# RS敏感性分析

## 一句话定义
通过系统化测试不同RS评分阈值，量化信号质量与交易频率之间的权衡关系，找到最优入场门槛。

## 核心要点
- 核心矛盾：RS门槛越高 → 信号质量越好 → 但交易次数越少 → 可能因频率不足而降低总收益
- 方法：对同一段历史数据，以多个RS阈值（如60/65/70/75/80/85）分别运行回测，对比绩效指标
- 关键输出指标：总交易数、胜率、平均R值、夏普比率、最大回撤、总收益率
- 优化目标：找到"胜率 × 交易频率"乘积最大化的RS阈值 — 即信号质量与数量的最优平衡点

## 敏感性的三个区域

| 维度 | RS低区（<65） | RS中区（65-75） | RS高区（>75） |
|------|-------------|---------------|-------------|
| 信号数量 | 多（含噪音信号） | 适中 | 少（可能错过良机） |
| 平均胜率 | 偏低 | 中等 | 高 |
| 平均R值 | 低 | 中等偏高 | 高 |
| 总收益潜力 | 取决于"以量补质"是否成立 | 通常为最优区 | 取决于"以质补量"是否成立 |
| 最大回撤 | 可能较大 | 可控 | 低 |

## 局限与注意事项

- **历史依赖性**：最优RS阈值在不同市场阶段可能漂移（牛市vs熊市vs震荡），需要滚动窗口验证
- **评分权重固定**：敏感性分析只能优化"已知评分体系下的阈值"，无法验证RS评分的10+2维度权重本身是否合理——如果评分维度设置有问题，再精细的阈值选择也无法修正
- **过拟合风险**：在单一历史区间上优化RS阈值可能过度拟合，建议使用样本外测试验证

## 与相关概念的关系

- ：敏感性分析直接操作RS阈值的输入变量，依赖评分系统提供的基础信号排序——评分系统是"打分的人"，敏感性分析是"定录取线的人"
- [[trade-management-system]]：不同RS阈值下的最优止损/止盈参数可能不同。高RS信号（如≥80）质量更高，理论上可使用更紧的止损；低RS信号（如≤65）需要更宽的止损空间
- [[trading-range-quality]]：TR逆势信号本身的RS偏低（通常在60-70区间），敏感性分析可揭示TR环境是否需要独立的RS门槛，而非与趋势信号共用同一阈值
- [[signal-dashboard]]：敏感性分析的结果直接影响信号面板的"历史回测统计"组件——不同RS阈值下的期望表现差异在此可视化

## 实战应用

在 `btc_price_action_backtest.py` 中通过 `--sensitivity` 标志启用：

```bash
# 以RS=75为基准，自动测试上下各2个档位
python btc_price_action_backtest.py --rs 75 --sensitivity --days 90
```

脚本自动以指定RS值为中心，上下各测试2-3个档位（如70/72/75/78/80），生成对比表格和可视化。A股分析系统（`a_share_price_action.py`）中可通过参数配置实现相同逻辑。

## 矛盾与待验证

- RS阈值的"最优值"是否具有跨市场普适性尚待验证：BTC（24×7高波动）的最优RS可能不同于A股（T+1低波动）的最优RS
- 当前敏感性分析的档位步长（±5）是否足够精细，是否需要非均匀步长（如在65-75关键区间加密测试），待实操验证
