# 信号面板

## 一句话定义
回测/实盘系统生成的实时市场诊断快照，将多维度价格行为分析合成为单一决策界面。

## 核心要点
- 不是简单的"买卖信号弹窗"，而是一个完整的市场状态诊断面板
- 整合了 7 大分析维度：K线标注、提醒卡片、检查清单、80/20规则、形态检测、波幅状态、历史统计
- 设计哲学：交易员可以用一瞥判断"当前该不该出手"——而不是让系统替你决策
- 存在两种使用场景：实时面板（--dashboard）用于盘中诊断，回测面板嵌入在10+7面板体系中作为事后分析

## 七大面板组件

| 组件 | 内容 | 决策用途 |
|------|------|---------|
| **K线图+信号标记** | 最近 K 线走势，信号位置以箭头标注 | 直观判断信号在图表中的位置、与 S/R 的关系 |
| **信号提醒卡片** | 入场方向、入场价、止损价、目标价 | 一目了然"如果入场，参数是什么" |
| **入场前检查清单** | 趋势方向、S/R 测试、信号结构、风险回报比等逐项 | 系统化的"最后一关"——避免冲动交易 |
| **80/20规则评估** | 当前价格在趋势/区间的什么位置——顺从80%还是赌20% | 判断顺势还是逆势——决定仓位大小和信心水平 |
| **检测到的形态** | 楔形、双顶/底、三角形等已触发形态列表 | 多信号共振确认——形态越多、级别越高，信号越可靠 |
| **波幅状态** | SPB/BTC/STC/TR 等当前市场动态模式 | 识别当前市场是在"趋势巡航"还是"区间震荡"，指导交易风格 |
| **历史回测统计** | 策略在此品种/周期的累计胜率、平均R、夏普 | 背景信心——"这个策略历史上的表现如何" |

## 与相关概念的关系

- [[live-trading-monitor]]：信号面板是监控系统的**内容层**——监控系统定义"怎么推送"，信号面板定义"推送什么"。监控系统解决技术架构（WebSocket/CLI），信号面板解决认知架构（诊断维度/决策流程）
- [[rs-scoring]]：信号面板上的信号提醒卡片中，入场价/止损/目标由 RS 评分系统计算得出。RS≥70% 的信号才会出现在面板上
- [[rs-sensitivity-analysis]]：敏感性分析的结果直接影响信号面板的"历史回测统计"区域——告诉交易员当前 RS 阈值下的期望表现
- [[brooks-signal-catalog]]：信号面板的"检测到的形态"组件列出当前 K 线上触发的所有信号类型，7大信号按优先级排序展示
- [[eighty-percent-rule]]：信号面板的"80/20规则评估"组件直接应用此概念——判断当前是做 80% 顺势方向还是 20% 逆势反转
- [[trade-management-system]]：提醒卡片上的入场/止损/目标由交易管理体系的6组件计算

## 实战应用

```bash
# 生成实时信号面板（仅诊断，不运行完整回测）
python btc_price_action_backtest.py --dashboard --days 14

# A股版本等效命令
python a_share_price_action.py --code sh.600519 --dashboard
```

信号面板适合在开盘前或盘中快速生成，帮助交易员：
1. 快速扫描 3-5 个品种的信号面板，锁定"最值得看"的品种
2. 对比入场前检查清单，验证自己的手动分析是否遗漏
3. 用80/20规则评估决定仓位大小

## 矛盾与待验证

- 信号面板是一个**辅助诊断工具**还是**决策替代工具**——官方定位为前者（工具/指南），但实际 UI 设计的"提醒卡片+检查清单"格式可能诱导交易员过度依赖。Brooks 原著强调交易员的自主判断，量化系统能否保持这种"工具辅助、人做决策"的边界，待长期使用验证
- 检查清单的具体条目是否与 Brooks 原著的前置条件完整对齐，尚无法验证（评分权重未公开）
