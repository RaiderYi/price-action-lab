# 一票否决闸门（Veto Decision Gate）

## 一句话定义
V6 在全部评分完成后执行的一票否决机制——6 种条件对应 6 种裁决文本，其中 4 种为否决（禁止交易）、2 种为绿灯（允许交易），优先级高于任何评分。

## 核心要点

### 否决条件表

```
震荡区间                      → "震荡内优先等待突破"         ← 否决
上涨趋势 + 贴近阻力            → "多头受阻力压制"             ← 否决
下跌趋势 + 贴近支撑            → "空头受支撑压制"             ← 否决
过渡阶段                      → "过渡期信号降级"             ← 否决
上涨趋势（其他情况）            → "顺势偏多有效"               ← 非否决
下跌趋势（其他情况）            → "顺势偏空有效"               ← 非否决
其他（兜底）                   → "等待更清晰背景"             ← 否决
```

### 判定优先级

条件按以下顺序从上到下短路求值（最先匹配即返回）：

1. `isRange` → 震荡否决（最高优先级——无论评分如何，震荡内不交易）
2. `isBullTrend and nearResistance` → 多头阻力压制（趋势方向正确，但位置不好）
3. `isBearTrend and nearSupport` → 空头支撑压制（同上）
4. `isTransition` → 过渡期否决（阶段不明确，信号不可靠）
5. `isBullTrend` → 顺势偏多有效（非否决——绿灯）
6. `isBearTrend` → 顺势偏空有效（非否决——绿灯）
7. 兜底 → 等待更清晰背景（否决——不应到达此分支的正常市场状态）

### 贴近判定

```
nearResistance = |lastHigh1 − close| ≤ ATR × 0.35  ← 可配
nearSupport    = |close − lastLow1| ≤ ATR × 0.35   ← 可配
```

参数 `srNearATR` 默认 0.35，可在 G1 参数组调整。

## 与已有否决系统的对比

| 维度 | 紧急逃生（emergExit） | V4.1/V5 背景否决 | V6 一票否决 |
|------|---------------------|-----------------|------------|
| 触发条件数 | 3 | 4 | 6 |
| 条件类型 | 纯K线形态（假突破/衰竭/竭尽） | 位置+阶段+成熟度混合 | 阶段×位置 的组合判定 |
| 覆盖率 | 仅覆盖极端K线异常 | 覆盖背景不合规场景 | 覆盖阶段+位置的全部组合 |
| 否决粒度 | 二元（触发/不触发） | 4类文本说明 | 6类精确文本 |
| 绿灯语义 | 无（不否决=通过） | 无 | 2条明确绿灯 |
| 对评分的影响 | 压低 ctx3_score（−26%） | 独立二元否决 | 独立二元否决 |

### 关键差异

- **紧急逃生**关注的是「当前K线是否异常」（假突破 / 衰竭 / 竭尽），是**微观异常检测**
- **V4.1/V5 背景否决**关注的是「整体背景是否支持交易」（中间位置+震荡 / 逆势趋势健康），是**中观背景审核**
- **V6 一票否决**将两者统一为「阶段×位置的组合判定」，用 6 个条件覆盖所有场景，是**统一决策闸门**

### 阶段×位置 决策矩阵

| ↓阶段 \ 位置→ | 贴近支撑 | 中间位置 | 贴近阻力 |
|---------------|---------|---------|---------|
| 上涨趋势 | 顺势偏多 ✓ | 顺势偏多 ✓ | **多头受阻力压制 ✗** |
| 下跌趋势 | **空头受支撑压制 ✗** | 顺势偏空 ✓ | 顺势偏空 ✓ |
| 震荡区间 | **震荡等待 ✗** | **震荡等待 ✗** | **震荡等待 ✗** |
| 过渡阶段 | **过渡降级 ✗** | **过渡降级 ✗** | **过渡降级 ✗** |

只有趋势+不贴近对向 S/R 的位置组合才是绿灯（4/12 = 33% 的场景）。

## 与相关概念的关系

- [[emergency-exit]]：V6 的一票否决是紧急逃生的演化升级——从 3 种 K 线异常扩展到 6 种阶段×位置组合判定
- [[ctx-scoring]]：Step4 否决（TR位置否决 + 逃生顺势否决）是 V6 一票否决的前身——V6 将所有否决合并到一个统一闸门
- [[background-scoring-engine]]：V4.1/V5 的背景否决（4条件）处于紧急逃生和 V6 一票否决之间——条件数 4 vs V6 的 6，但缺少「过渡期」和「兜底」两个覆盖
- [[background-permission]]：V6 的一票否决本质上是简化版的背景许可门控——将 allowLong/Short/veto/conflict 复杂逻辑简化为 6 条短路规则
- [[support-resistance|Support/Resistance]]：贴近判定（ATR×0.35）是 V6 否决系统的核心输入——S/R 的精确性直接影响否决质量

## 实战应用

在 V6 状态面板中，第 8 行显示：
```
一票否决   多头受阻力压制
```

交易者决策流程：
1. 先看面板最后一行 → 只要是前 4 种否决文本 → 不做任何交易
2. 如果是「顺势偏多/偏空有效」→ 再看动能/健康评分确认趋势质量
3. 「震荡内优先等待突破」→ 最高频的否决（大多数市场时间处于震荡或类震荡状态）
4. 「过渡期信号降级」→ 警告但不一定是绝对禁止——老手可能在过渡期低仓位试探

**一票否决的设计哲学**：守株待兔——宁可错过震荡中的 100 次假突破，也不在不利环境下入场。这完全符合 Brooks 的核心原则「wait for the context to be clear」。

## 矛盾与待验证

- V6 的否决是**纯可视化参考**——不硬性拦截信号（因为 V6 根本没有信号层）。这与 V4.1/V5 的硬否决（真正拦截 `longSig`/`shortSig`）不同——V6 的否决依赖交易者自律
- 震荡否决（条件1）过于绝对——区间内的反转交易（如 Brooks 的「区间内反转」策略）被一并否决，可能过杀
- 贴近阈值 0.35×ATR 可能太窄——在高波动市场中，0.35×ATR 仍然距离 S/R 很远，但被判定为「贴近」而否决
- V6 缺少「成熟度/衰竭」维度的否决——V4.1 的「高成熟度+衰竭+目标」三重叠加否决在 V6 中完全消失
