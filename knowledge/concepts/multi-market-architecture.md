# 多市场架构

## 一句话定义
同一套 Al Brooks 价格行为策略引擎在 BTC（加密货币）和 A股（沪深）两个市场同时部署的系统架构设计。

## 核心要点
- 策略核心（7 信号 + RS 评分 + 交易管理）在所有市场中完全一致
- 数据源层做市场适配：Binance API（加密货币） vs baostock（A股）
- A股版本额外处理：复权（前/后/不）、交易日历、收盘时间断点

## 架构分层

```
┌──────────────────────────────────────────┐
│          统一策略引擎                      │
│  7大信号 · RS评分 · 交易管理 · 绩效分析     │
├──────────────────────────────────────────┤
│       数据适配层                           │
│  ┌──────────────┐  ┌──────────────┐       │
│  │ Binance 适配  │  │ baostock 适配 │       │
│  │ (24×7, 无复权)│  │ (9:30-15,复权)│      │
│  └──────────────┘  └──────────────┘       │
├──────────────────────────────────────────┤
│       运行模式                             │
│  批处理回测 · 命令行实时 · Web界面          │
└──────────────────────────────────────────┘
```

## 市场差异对比

| 维度 | BTC（加密货币） | A股 |
|------|----------------|-----|
| 数据源 | Binance API | baostock |
| 数据量限制 | 单次 ≤1000 条 | 全量历史（1990起） |
| 交易时间 | 24×7 连续 | 9:30–15:00 有断点 |
| 复权 | 不涉及 | 前复权/后复权/不复权 |
| 网络 | 需访问 api.binance.com | 国内直连 |
| 交易日历 | 无（每天交易） | 自动处理节假日 |

## 与相关概念的关系
- [[brooks-signal-catalog]]：跨市场验证了 Brooks 方法的普适性——同一信号在 BTC 和 A股均可产生有效信号
- [[trade-management-system]]：交易管理体系在所有市场中复用，但时间止损阈值需按各市场交易时间调整
- [[adjustment-factor]]：A 股独有的复权概念——后复权是数据适配层的核心功能，直接影响回测精度和信号识别

## 实战应用
研究跨市场策略时，可在 BTC 版本快速验证信号逻辑（24×7 连续数据、无复权干扰），确认有效后再用 A股版本做国内实盘适配。

## 矛盾与待验证
- **策略通用性假设**：Brooks 方法论最初针对美股指数期货（MES），拓展到 A股需验证是否有"水土不服"——A股涨跌停板、T+1 制度、散户主导的市场结构可能影响信号有效性
- **数据频率差异**：BTC 支持 1m/5m 等高频周期，A股最短仅 5m（且盘中数据量有限），高频策略的跨市场对比需统一到 5m 或更高周期
